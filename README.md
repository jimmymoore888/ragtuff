# RagTuff

RagTuff is the governing invariant architecture. Execution systems must conform to it; they do not define it.

RagTuff does not belong to DeFi.
DeFi conforms to RagTuff.

RagTuff does not serve AI treasuries.
AI treasuries must obey RagTuff.

## Canonical Definition

RagTuff is a **non-executable, advisory-only constitutional framework** for high-consequence decision environments.

It is designed to model, evaluate, and position decisions under financial, adversarial, and systemic pressure without ever assuming execution authority.

RagTuff does not act.  
RagTuff does not control.  
RagTuff does not execute.

It provides structured orientation under constraint.

## Structural Separation

RagTuff exists in two distinct layers:

### 1. RagTuff (Framework)

This repository defines a:

- Decision-support system  
- Consequence modeling framework  
- Defensive and adversarial analysis tool  
- Counter-improvement measurement structure  
- Cryptographically integrity-preserving specification  

It is advisory-only.

It has no execution authority.

It is not deployable software.

It is not a standalone application.

It contains no runnable entrypoint by design.

---

### 2. RagTuff Core (External Invariant Instantiation)

RagTuff Core refers to optional external smart-contract implementations that encode invariant economic law derived from the RagTuff framework.

Those deployments may enforce:

- Fixed or bounded supply mechanics  
- Treasury partitioning  
- Timelocks and unlock schedules  
- Burn ceilings  
- Immutable economic constraints  

These implementations are separate sovereign deployments.

This repository does not deploy, control, upgrade, or execute them.

---

## Operator (Human Layer)

RagTuff explicitly separates framework evolution from deployed invariant law.

These authorities are distinct.

---

### A. Builder Governance (Framework Layer — Mutable)

Builders retain authority over:

- Documentation and specification refinement  
- Module and tooling development  
- External integration patterns  
- Factory and deployment reference designs  

Builders evolve the framework.

This layer is mutable.

---

### B. Invariant Sovereignty (Deployed Law Layer — Immutable)

Once a RagTuff Core implementation is instantiated externally, builders permanently relinquish authority over its defined invariants.

No builder, operator, governance process, or automated system may override:

- Supply mechanics  
- Treasury partitioning  
- Timelocks  
- Burn ceilings  
- Core economic invariants  
- Emergency override restrictions  

That layer is immutable by design.

---

### Summary

Builders govern the framework.

Invariants govern deployments.

Humans evolve tools.  
Law governs outcomes.

## Operator Invariants (Human Layer)

RagTuff encodes behavioral continuity principles:

**INV-H1 — Continuous Activity**  
Avoid prolonged stagnation. Minimal forward motion is preferable to idle collapse.

**INV-H2 — Monotonic Forward Delta**  
Each iteration must produce a non-negative state transition.

**INV-H3 — Momentum Preservation**  
Interruptions may occur; forward velocity must be restored without drift.

**INV-H4 — Reality Priority**  
External survival constraints (health, income, safety) supersede build velocity.

These govern operator discipline — not machine execution.

## What RagTuff Is Not

RagTuff is not:

- An execution engine  
- A routing system  
- A transaction processor  
- A custodian of funds or keys  
- A controller of infrastructure  
- An autonomous agent  
- A governance authority  
- A monetization layer  

RagTuff does not issue commands.  
RagTuff does not assume custody.  
RagTuff does not initiate action.

All execution authority remains external.
